Start with intent.

A new org cannot explain the process the customer wants. An existing org can reveal configuration, but it cannot decide whether that behavior is intended, legacy or a bug.

Record the owner’s decision before turning the configuration into an expected result.

Finish with evidence.

Map approved requirements to role, boundary and integration checks. Review actual results and retain the link to the rule version.

Then make that evidence useful as a customer guide and a baseline for future changes.
