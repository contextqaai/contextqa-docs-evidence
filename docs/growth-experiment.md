# Growth experiment: workflow evidence for living documentation

**Hypothesis:** teams already maintaining guides and demos will try ContextQA when a repeatable workflow can also supply reviewed screenshots and release-aware documentation evidence. Repeat refreshes, rather than one-off screenshot downloads, may create durable paid usage.

## Proposed bounded pilot

Choose three consenting design partners: one documentation platform/team, one interactive demo team and one product/support documentation owner. Layerpath and EkLine are examples of relevant workflows; neither is enrolled or contacted by this project. For each, choose two high-maintenance tasks and compare one existing manual update with one wrapper-assisted update. No outreach, paid service, schedule or campaign is activated here.

Offer a synthetic example and a private demo-tenant trial. Show the task, reviewed screenshot guide, release change context, explicit old/new comparison and draft update. Ask whether their existing agent/editor can use the output without a new platform-specific adapter. Capture friction before adding automatic publishing.

## Measurement definitions and proposed gates

| Measure | Definition | Proposed decision gate |
| --- | --- | --- |
| Activation | Partner creates one reviewed package and uses it in an actual draft | At least 2 of 3 partners |
| Refresh success | Same task refreshed after a real app change, with accepted docs update | At least 2 partners complete a second cycle |
| Author effort | Active capture, selection, review and editing minutes, compared on the same task | Median effort falls at least 30%; report sample size |
| Quality | Reviewer-accepted correctness, working media/links and no stale instructions | All published pilot updates pass owner review |
| Safe export | Unapproved raw data or sensitive evidence appears in shared output | Zero incidents; hold sharing immediately if found |
| Commercial signal | Partner requests continued usage and names a viable buyer/budget | Two explicit conversations before building billing |

These are hypotheses and proposed thresholds, not achieved results. Record failures and review effort, including time spent redacting images; do not count generated drafts as published docs or paid adoption.

## Monetization to validate

Start with existing ContextQA workflow execution usage plus a proposed evidence/refresh tier. Potential paid dimensions are successful workflow runs, selected media storage/retention and refresh volume. Meter actual cost of execution, model calls, storage, egress, retries and support. Do not charge per poll or count a failed/retried run twice without an agreed policy. Establish contribution margin before quoting prices. No pricing, billing or customer commitments are changed by this repository.

## Roadmap after evidence of demand

1. Reliable capture producer with task identity, release metadata and stable step IDs.
2. Evidence dependency map connecting workflows to docs pages, tours, languages and owners.
3. Reviewed visual comparison, metadata stripping and stronger PII review tooling.
4. Documented partner API adapters only after vendor access is verified.
5. Release-triggered draft PRs with scoped credentials, idempotency, cost caps, tenant isolation and human publication approval.

The current prototype supplies a local evidence wrapper and explicit comparison draft. It does not offer a Browserbase-style live CDP browser, automatic screenshot recapture, release monitoring or a hosted monetization product.
