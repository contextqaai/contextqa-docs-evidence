## UTM convention

Use `utm_source=github`, `utm_medium=developer_referral`, `utm_campaign=contextqa_docs_evidence`, and a descriptive placement in `utm_content`. For the n8n repo use campaign `contextqa_n8n`. These are proposed repo-attribution conventions, not a claim that conversion analytics or reporting has been configured.

Add UTM parameters to human-facing ContextQA marketing/tutorial/blog links only. Never change API origins, authenticated artifact URLs, OAuth callbacks, signed media links or credential destinations for marketing tracking. Avoid internal project/customer names or personal data in UTM values. Preserve canonical URLs for technical source citations.

No relevant n8n-specific ContextQA blog was verified during this update; the MCP article is adjacent guidance rather than a native n8n tutorial. No partnership or product capability is implied by linking an article.
